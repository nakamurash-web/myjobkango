`nurse-lp-demo.html` … 検索KW（`?st=`）に応じて FV・記事内ブロックを差し替える単一ページのデモ。
ローカル検証 → Squad beyond のHTMLエディタへ貼り付け、まで1ファイルで完結する。

## Q&A（構築前の3つのネック）

### 1. レスポンシブ表示はどうテストする？
ローカルHTML + Chrome DevTools が最速（beyondプレビューだと `?st=` 検証がしづらい）。

1. `nurse-lp-demo.html` をブラウザで開く（ダブルクリックでOK）
2. F12 → デバイスツールバー（Ctrl+Shift+M）
3. **「ブレークポイント × KWパターン」のマトリクス**で確認：

| 幅 | 端末目安 | 確認URL例 |
|---|---|---|
| 375px | iPhone SE | `?st=看護師 夜勤なし` |
| 390px | iPhone 14 | `?st=看護師 ブランク 復職` |
| 768px | iPad | `?st=美容クリニック 看護師` |
| 1280px | PC | `?st=20代 看護師`（直アクセスも確認）|

> 実機確認は beyond のプレビューURLに `?st=...` を付けてスマホで開く。

### 2. 複雑設計でリンクが正しく入るか不安 → `?debug=1` で自己チェック
末尾に `?debug=1` を付けると、画面左下に検査パネルが出る：
- 出し分け判定（`<html class="...">`）
- クリックID保存状況
- **全アフィリンクのCV属性・差し替え漏れ（`example.com` のままなら赤で警告）**
- 現在表示中のブロック

例: `nurse-lp-demo.html?st=看護師 夜勤なし&area=中央区&gclid=TEST123&debug=1`

### 3. 複数ページ？単一ページ？ → **デモは単一ページでOK**
広告KWの出し分けはSEO不要なので **1ページ多態**で完結。
beyond的には「ab_testページ1つ + HTMLエディタ版version 1つ」。
Branch Operation（設定での出し分け）や複数ページは、エリア別SEO量産やAB配信を始める段階で導入すればよい。

## KW出し分けの優先順位（重複対策）
検索KWは重複しうる（例「外来 日勤のみ」）。`else if` の順＝優先順位を明示的に定義：

```
夜勤なし（日勤のみ含む） ＞ ブランク復職 ＞ クリニック
```

| 検索KW例 | 判定 |
|---|---|
| 看護師 夜勤なし / 夜勤 したくない / 外来 日勤のみ | 夜勤なし |
| ブランク / 復職 / ママナース | ブランク復職 |
| 美容クリニック / 外来 | クリニック |
| 夜勤専従 高収入（夜勤希望） | どれにも当たらない → デフォルト表示 |

## テスト（出荷コードをそのまま実行）
`segment.test.mjs` は、HTML内の判定スクリプトを**実コードのまま**抜き出して実行し、
KW→クラス付与・エリア差し込み・クリックID保存・CSS表示契約を検証する。

```bash
node demo/segment.test.mjs
# => 17 passed / 0 failed
```

KW分岐の正規表現を編集したら、必ずこのテストを通すこと。
